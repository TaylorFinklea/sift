# Sift transfer format

The portable archive is UTF-8 JSON. Version 1 remains the canonical shape for choice-only libraries; version 2 is used when numeric card values or rating rounds occur:

```json
{"format":"sift","version":1,"exportedAt":"2026-11-06T12:00:00.000Z","collections":[{"id":"UUID","records":[{"id":"UUID","kind":"collectionRevision","version":1,"ownerID":"UUID","logicalID":"UUID","payload":"BASE64_UTF8_JSON"}]}]}
```

Each bundle is one complete logical collection. Its `records` contain every collection revision, referenced card revision, sort session snapshot, and sort action, including alternate branches. A `DomainRecord` payload is the exact JSONEncoder representation used by Sift Core: sorted JSON keys, dates in milliseconds since 1970, then base64 encoded. The record envelope's UUIDs are uppercase. The base64 payload is retained byte for byte when an archive is normalized or imported and exported again.

Supported payload record types are `collectionRevision`, `cardRevision`, `sortSession`, and `sortAction`. Version 1 preserves its existing bytes and omits empty optional additions. Version 2 carries `NumericField` definitions in collection revisions, explicit card values keyed by field UUID in card revisions, the same field definitions as a sort-session snapshot, and rating scales on rating rounds. Rating decisions encode `choice: "rating"` with a numeric `value`; keep/discard decisions never have a value. Every version-2 sort action has matching `schemaVersion: 2` and `rulesVersion: 2`. Readers reject version-1 envelopes or records that contain rating or numeric semantics instead of ignoring those fields. An envelope becomes version 2 if any record is version 2; a mixed envelope can retain untouched version-1 records.

`NumericScale` contains `name`, `minimum`, `maximum`, `step`, and required `unit`. Values are finite, bounded, at most six decimal places, and must fall on the grid relative to `minimum`; invalid values are rejected, not clamped. A `NumericField` adds a stable UUID `id`. Card `numericValues` only contains explicit assignments. Rating scales do not have IDs and are immutable once their round starts. Each run’s `numericFields` and `ratingScale` are snapshots; exports never infer a historical run’s scale from the collection’s current editor state.

The shared bridge exposes:

- `validateTransfer(value)`: validates caps, record payloads, identity metadata, and dependency closure; returns normalized envelope or throws `TransferValidationError`.
- `webWorkspaceToTransfer({collections,runs,preservedRecords}, options)`: maps mutable web DTOs to native records. Existing native records should be passed as `preservedRecords` and retained unchanged. Web history can reconstruct recorded decisions, undo/replacement references, card snapshots and current queue order. The web DTO has no historical skip or plan-edit event stream, so a capture may encode final pending order as normalization actions at the last known row update timestamp; these are not claimed to be the original chronology.
- `transferToWebWorkspace(archive)`: returns `{collections,runs,records,collectionAlternatives}`. Each native path has its own web sort identity, round chain, and globally unique projected decision IDs. `revisesRunId` links a revised round to its original source when that source is a retained branch head. `collections` exposes every current collection leaf as a separate editable DTO. Each has `transferBundleID` (the logical native bundle UUID) and `sourceRevisionID` (its native revision UUID). The lexicographically first leaf uses the bundle UUID as its web `id`; each alternate uses the deterministic UUID derived from `sift-web-collection-version-v1|BUNDLE_UUID|REVISION_UUID`. `collectionAlternatives` repeats this version metadata for compatibility. Keep `records` as canonical history; web DTOs are editable projections and cannot carry every native branch or action.
- `remapTransferBundleIDs(archive, sourceBundleID, conflictingIDs)`: makes a deterministic whole-bundle identity remap for an alternate copy. The remap namespace hashes `sift-transfer-remap-v1\n` plus the sorted record identity lines; UUID references are rewritten only at known schema fields, including numeric field definitions and `numericValues` keys. UUID-looking field names, units, titles, details and labels remain literal text.

Archives are limited to 16 MiB, 20,000 records and 100 collection bundles. Exceeding a limit is an error; records are never truncated. A duplicate record ID with different envelope or payload content is rejected.

Web round rows belonging to one sort are captured in one native session. The next round receives all cards in the prior rating round's original order, or only the kept cards from the prior choice round, regardless of the next round's type. An earlier-round answer revision forks from the original later-round head with `revisedPath`. Cloned web decisions match source decisions by position, original time, card, choice, and value. A web replacement target's `undoneAt` is not itself an undo action; undoing the replacement restores the original answer. Current collection content is a descendant of captured historical snapshots so an old run snapshot cannot become the selected editable collection.

When canonical records accompany an unchanged imported projection, export returns those exact records, with no regenerated sessions, collection versions or actions. Edits to imported active rounds extend the existing native graph; collection edits append a collection revision. The original records remain in the archive. This requires the server to retain the complete canonical `records` sidecar alongside the SQL projections.

Validation checks that every action belongs to a leaf's complete ancestry and rejects disconnected cycles, then checks each path with the same round order, branch transitions, keep caps, effective replacement targets, undo order and started-round plan restrictions as Sift Core. It also rejects mismatched session snapshots, missing owners or parents, collection cycles, unsupported action versions and malformed operation payloads. No partial projection is accepted. Existing native limits apply: 500 cards, 50 rounds, 120 graphemes per card title, 500 per description/detail, and ten pros or cons of 200 graphemes each. Legacy web data beyond these limits fails export explicitly.

Deterministic conflict identity uses SHA-256 over UTF-8. Sort record envelopes by uppercase record UUID, and join lines `id|kind|version|ownerID|logicalID|payload` with LF. Prefix `sift-transfer-remap-v1` and LF, then hash to a lowercase hexadecimal namespace. For each known UUID reference, hash `namespace|UPPERCASE_UUID`; take the first 16 digest bytes, set the version nibble to 8 and the RFC variant bits to `10`, and format an uppercase UUID. The archive timestamp is excluded. Rewrite only typed identity/reference fields, including round-plan and decision IDs; UUID-looking text in titles, details or labels stays literal. Re-encode rewritten payloads as sorted-key UTF-8 JSON. The shared full-history fixture maps to collection `97F33C2D-9700-80EF-B2F0-F16261AE0B5D` in both JavaScript and Swift.

Recorded later rounds accept a keep limit from 1 through the number of incoming kept cards, including equality. This preserves valid website histories without changing their recorded limit or answers. Native sort creation may continue to offer a strictly reducing refinement by default.

The web backend persists each physical collection row's `transferBundleID` and `sourceRevisionID` in its version mapping and returns both fields on export. The shared exporter groups physical rows by `transferBundleID`, emits one complete native bundle, and compares each editable DTO with its `sourceRevisionID`. An edit appends a child of that source revision, preserving sibling versions and all original records. Sessions with an unambiguous source version attach to that editable row; shared-ancestor history stays on the primary row. History is projected once.

When exporting one physical collection/version, the backend must supply all version rows, runs and canonical records for its logical bundle. `options.collectionId` selects that logical bundle through the requested physical row, so a single-version export includes the complete original collection history and all alternate versions. Unchanged projections re-export every canonical record byte for byte.
