5. Valid website plan edits allegedly change started limits during export: rejected. Both backend plan handlers restore started caps from existing runs; allowed titles/future presets replay after the fork resets its active round.

## Limits and release boundary

The website's original mutable schema did not record a chronological skip/plan-edit event stream. Exports preserve the recorded audit and captured queue/plan state, not nonexistent original chronology. Native histories retain their exact canonical events. Transfer limits are 16 MiB / 100 logical collections / 20,000 records; larger or invalid archives fail explicitly. Website transfer requires its server connection; native file import remains local/offline. Account state, credentials/API keys and CKSyncEngine checkpoints are excluded.

Production D1 must receive additive migration 0004 only in a separately approved release. The website and existing TestFlight build do not yet include this local feature. Physical Files/share delivery and cross-device CloudKit convergence remain unverified.

Final source checksums are in [the final source manifest](transfer-final-source-manifest.json); the earlier packet manifest identifies the separate Ollama review snapshot. The two backend receipt/collision repairs and native copy/test-only refinements received independent Sol delta review.
